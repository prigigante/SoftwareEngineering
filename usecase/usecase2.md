## 유즈 케이스란?  

말 그대로 사용 사례를 보여주는 것  

유즈케이스는 각 단체, 기업등등마다 중점, 관점등이 다를 수는 있으나 다음의 3가지 요소는 거의 필수적으로 중요한 요소이다.  

| 중요점 | 세부내용 |
|-----|------|
|행위자| 단일 사용자, 팀, 다른 소프트웨어 등 **시스템과 상호작용 하는 주체** |
|시스템| 정의된 기능을 가진 제품 또는 서비스 |
|목표| 사용자가 시스템의 기능을 통해 달성하는 목적 또는 목표 |

이 3가지 기본 요소는 유즈케이스의 기초를 형성한다.   
시스템 상호작용을 추적하기 시작하면, 몇 가지 새로운 요소를 고려해야함  

| 추가 고려 요소 | 세부 내용 |
|--------------|------------|
|이해관계자||
|주행위자||
|전제조건||
|트리거||
|기본흐름||
|대체흐름||


## 사용사례 유형

사용사례는   

1. 비즈니스 형태
2. 시스템 형태

의 두가지 형태로 기본적으로 제공된다.  

### 시스템 유즈 케이스  

사용자가 시스템의 각 구성요소와 **어떻게 상호작용 하는지** 보여준다.   
고유 입력 **상황에 따라**, 시스템이 서로 **다른 결과**를 **도출하는 방식**을 강조.  
이러한 수준의 세부 정보는, **시스템의 개별 기능**이 **어떤 시나리오**에서든 **어떻게 작동**하는지 보여준다.    


### 비즈니스 유즈 케이스

비즈니스의 경우에는 사용자가 목표달성을 위해, 비즈니스와 상호작용하는 더 일반적인 방법에 대해 제공.  
기술적인 세부사항이 초점이 아닌, 다양한 입력이 가져오는 결과를 인과관계로 설명  
예시로, 코드 디버깅 플랫폼의 경우  
비즈니스 사용 사례에서는 사용자가 코드를 입력하고 오류 알림을 받는 과정을 설명(기술적으로 어떻게가 아니라는 것에 유의깊게 생각해 볼것)  



## 사용 시나리오 Vs. 사용 사례(유즈케이스)  

| 사용사례 | 사용 시나리오 |
|--|--|
|목표 달성을 위해 시스템이   작동하는 모든 방식을 기술| 한가지 사례만 기술 |
| ? | 사용자 목표를 달성하는데 성공할 수도, 실패할 수도 있음 |

 ### 다양한 사용시나리오의 모음 ==> 하나의 사용 사례  
 

## 사용 사례 Vs. 사용자 스토리

| 사용 사례 | 사용자 스토리 |
|----------|-------|
|사용자가 시스템과 어떻게 사용작용 하는지 | 사용자 관점에서 기능을 설명 |
| 상대적으로 김 | 사용사례보다 훨씬 짧음 |
| 오거니제이션 내 여러팀에 도움 가능 | 제품 팀이 도구를 구축하는데 도움 가능 |

## 사용 사례 Vs. 테스트 케이스

| 사용 사례 | 테스트 케이스 |
|----|-----|
|사용자 & 시스템 기능이 목표 달성을 위해 **어떻게 동작**하는지 | 단일 기능이 올바르게 동작하는지 검증 |
| 우측과 다름 | 기능을 개별적으로 살펴봄 |
