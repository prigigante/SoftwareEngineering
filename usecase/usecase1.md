# 유즈케이스 정의

유즈케이스는 role 과 task에 근거하여, 요구사항의 set을 다듬기 위해서 구축됩니다.  
아마도 직접적으로 솔루션의 사용(use)를 가리키지 않는 전통적인 요구 리스트를 대신하여, 유즈케이스는 역할이나 목표 유형에 따라 공통적인 요구사항을 그룹화 합니다.  
유즈케이스는 사용자 또는 역할이 솔루션에서 수행하는 작업을 정의하는 반면에, 비즈니스 프로세스는 이러한 기능을 수행하는 방식을 정의합니다.  

유즈케이스는 액터가 수행할 수 있는 작업 목록을 나타내며, 비즈니스 프로세스의 요구사항과 직접적으로 연관되어 있습니다.  
use case는 프로젝트가 반드시 달성해야하는 요구사항의 확인 사항입니다.  
use case를 문서화하기 위해서는 목적 요구사항을 정의하고, 소개를 제공하며, 주어진 시나리오에 대한 서로다른 액터 또는 역할을 나열해야합니다.

### 유즈케이스 작성 절차

1. 액터를 식별 & 정의
2. 1. 시스템의 모든 주요 이용자 식별. 주요 이용자는 시스템이 구축되는 대상 이용자
   2. 자동화된 시스템과 지원 및 관리 역할의 사용자들을 포함, 시스템의 모든 다른 사용자들을 식별
  >> 전자 매장에서 새로운 제품을 소개하려면, 마케팅 역할의 사람이 상품 설명을 작성해야 하고, 공급업체가 제공하지 않은 경우 사진 부서의 누군가가 제품 사진을 제공해야 한다. 따라서 사용자 역할 목록에는 공급업체(vendor), 마케팅 역할, 사진가 역할이 포함되며, 각각은 신규 제품 소개 use case에서 역할을 수행한다. 여기서 공급업체는 검토를 위해 제품을 제출하고, 마케팅 역할은 새로운 제품을 소개하며, 사진가는 사진을 촬영한다.
공급업체가 수행하는 작업은 자체 use case이다. 마케팅 담당자가 수행하는 작업은 별도의, 관련된 use case이다. 사진가가 수행하는 작업은 세 번째 관련 use case이다.
3. 사용자 요구사항을 use case에 매칭, use case 탬플릿을 사용하여 역할의 이름과 설명을 문서화

>> 세 가지 사용자 역할이 있다: 공급업체(vendor), 마케팅 역할, 사진가.
마케팅 역할은 제품 소개를 담당한다. 이 역할의 사용자들은 제품 정보를 작성하고, 제품이 무엇을 하는지 이해하기 위해 제품을 사용해야 한다. 마케팅 담당자는 다른 사용자 역할에 의존한다.
사진가는 제품의 사진을 하드카피 또는 소프트카피용으로 촬영하는 일을 담당한다.
공급업체는 제품을 검토를 위해 제출하는 일을 담당한다.

예시

아래 템플릿은 업계 표준 출처에서 가져온 샘플이며 use case를 문서화하는 데 사용할 수 있다.
|유즈케이스 필드|설명|
|:---------------------:|:----------------------|
| Use-case | 필드	설명|
| Use case name | 특정 작업을 설명하는 능동 동사구. |
| Subject area | use role 또는 use case를 그룹화하는 데 사용할 수 있는 기타 그룹화 메커니즘. |
| Business event | 비즈니스 내에서 활동을 자극하는 트리거. 많은 비즈니스 이벤트는 비즈니스와 상호작용하는 외부 엔터티 사이의 인터페이스 지점에서 발생한다. 비즈니스 이벤트는 관찰 가능해야 한다. |
| Actors | 이 use case를 시작하는 액터와 이 use case에 참여하는 모든 사용자. |
| Use case overview | use case의 전체 범위와 내용을 설명. |
| Preconditions | use case가 솔루션 개발자가 워크플로를 생성하는 데 사용되기 위해 충족되어야 하는 제약 조건. 여기에는 use case의 수행 순서 요구사항이 포함될 수 있다. 예를 들어, 이 use case를 시작하기 위해 하나 이상의 다른 use case가 성공적으로 수행되어야 할 수도 있다. |
| Termination outcome | use case가 끝날 수 있는 성공적 혹은 비성공적 방법 목록. 가능한 종료 결과는 무엇인가? |
| Condition affecting termination outcome | 해당 종료 결과가 발생하는 조건 목록. |
| Use case description | 가장 가능성이 높은 종료 결과에 대한 사건의 간단한 설명. 액터가 수행하는 행동과 시스템의 반응을 나열한다. |
| Use case associations | 이 use case와 연관된 다른 use case 목록. |
| Traceability to | 이 use case와 연관된 다른 문서, 모델 및 제품 목록. |
| Input summary | 액터가 입력하는 데이터 목록에 대한 간단한 요약. |
| Output summary | 시스템이 출력하는 데이터 목록에 대한 간단한 요약. |
| Usability index | 만족도, 중요성, 빈도 측면에서 이 use case가 평가된 수치. |
| Use case notes | 이 use case의 직접적인 일부는 아니지만, 솔루션 개발자가 워크플로를 작업할 때 알아야 하는 정보. |
